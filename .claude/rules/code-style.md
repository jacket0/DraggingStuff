# Стиль кода C# (DruggingStuff)

Применяется ко всем `.cs` файлам проекта. Общие правила Михаила главнее, здесь они конкретизированы под этот проект.

## Принципы
- Главное: корректность, понятность, простота, поддерживаемость.
- Общепринятые практики C# и Unity. ООП, SOLID, KISS там, где реально улучшают решение. Без паттернов, интерфейсов, абстракций и слоёв ради принципов. Самое простое корректное решение лучше изящного.
- Если используешь паттерн или принимаешь важное архитектурное решение, коротко назови его в ответе.
- Учитывать существующую архитектуру и стиль. Не переписывать рабочее и не вводить новые технологии без веской причины; крупное изменение предлагать с плюсами и минусами.
- Неоднозначность, влияющую на поведение, архитектуру, данные или публичный API, уточнять. В остальном выбирать разумный вариант и называть допущение.
- Чинить причину, а не симптом. Не трогать логику, не связанную с задачей.

## Именование
- Имена однозначные и простые, без сокращений и слишком общих слов (`Manager`, `Data`, `Helper` без уточнения).
- Классы и методы: PascalCase. Приватные поля: `_camelCase`. Константы: PascalCase.
- События: глагол в прошедшем времени (`ShiftCompleted`, `MatchSucceeded`), обработчики обычно `Handle...`.

## Комментарии
- Комментарии в коде не писать. Если без комментария непонятно, упростить код: вынести метод, переименовать, разбить.

## Оформление
- Без namespace и без asmdef, как во всём проекте.
- Классы без наследников помечать `sealed`.
- Явные типы вместо `var`.
- Однострочные `if` без фигурных скобок; пустая строка после блока `if` перед следующей логикой.
- Expression-bodied члены там, где выражение короткое.
- Коллекции полей инициализировать сразу: `private readonly List<T> _items = new List<T>();`.

## Unity-компоненты
- Зависимости приходят ссылками из инспектора: `[SerializeField] private`. DI-фреймворка нет и добавлять его не нужно; поиск объектов по сцене (`FindObjectOfType`) без веской причины не использовать.
- Обязательные ссылки проверять в `Awake` и падать сразу: `throw new InvalidOperationException(nameof(_field));`.
- Подписка на события в `OnEnable`, отписка в `OnDisable`. Каждая подписка обязана иметь отписку.
- Наружу: свойства только для чтения и `event Action...`; поля не публиковать.
- Настройки и данные: `ScriptableObject` с `[CreateAssetMenu(menuName = "Game/...")]`.
- Числовые настройки в инспекторе ограничивать `[Min]`. При переименовании сериализованного поля ставить `[FormerlySerializedAs]`, чтобы не потерять значения в сценах.
- Тайминги: корутины. Анимации: DOTween. `async`/`await` и UniTask в проекте не используются.

## Логика
- Правила игры держать в чистом C# (`Model/`, симулятор, снимки состояния), без зависимостей от Unity там, где это уже так.
- Аргументы публичных методов проверять: `ArgumentNullException`, `ArgumentOutOfRangeException`.
- Вызовы платформы (`YG2`) только в `Platform/Yandex` или там, где это уже принято; остальной код работает через интерфейсы.
